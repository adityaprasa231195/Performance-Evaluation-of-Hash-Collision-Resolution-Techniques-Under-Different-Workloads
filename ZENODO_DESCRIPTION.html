1. Abstract & Research Overview

Hash tables are foundational data structures utilized across compilers, database indices, operating system kernels, language runtimes, and high-throughput network stream engines. While standard theoretical models under the Simple Uniform Hashing Assumption (SUHA) predict uniform O(1) average-case complexity, real-world execution characteristics on modern superscalar processors are dictated by hardware cache hierarchies, spatial locality, branch predictability, and dynamic allocation latency.

This open-access research repository provides a complete, academically rigorous, and fully reproducible comparative study evaluating the four primary hash collision resolution paradigms:

  1. Separate Chaining (SC): Closed addressing implemented via vector-of-buckets with dynamically allocated node vectors (Vec<Vec<(i64, i64)>>).
  2. Linear Probing (LP): Open addressing with sequential probe stride (c = 1), power-of-two table capacity bitmask indexing, and tombstone markers for deletion.
  3. Quadratic Probing (QP): Open addressing employing triangular quadratic displacement (h(k, i) = (h(k) + i2) mod M) with prime table capacities ensuring complete cycle coverage up to load factor α ≤ 0.50.
  4. Robin Hood Hashing (RH): Open addressing with probe sequence length (PSL) displacement tracking, "rich-from-poor" item displacement, backward-shift deletion without tombstones, and early-termination search.

All implementations operate on 64-bit integer key-value pairs ((i64, i64)), share an identical deterministic 64-bit FNV-1a hash function with an explicit seed, and do not rely on standard-library hash maps.

2. Key Empirical Findings

Extracted from 3,920 controlled trials across 5 dataset scales (103 to 106 keys), 7 synthetic key distributions (Uniform, Normal, Clustered, Sparse, Dense, Heavy-hitter, Sequential), and 4 core operations (Insert, Lookup Hit, Lookup Miss, Delete):

  • Hardware Cache Locality Dominance: For dataset sizes fitting inside the CPU L3 cache (≤ 105 elements), Linear Probing achieves the lowest lookup latency (12.29 ns), outperforming all other techniques due to contiguous array layout maximizing CPU L1/L2 hardware prefetcher efficiency.
  • Primary Clustering Pathology in Linear Probing: Under high load factors and non-uniform distributions, Linear Probing exhibits severe primary clustering, with maximum probe sequence lengths expanding up to 47–51 slots, degrading miss lookups and insertions.
  • Variance Compression in Robin Hood Hashing: Robin Hood hashing compresses the probe distribution variance, strictly bounding maximum probe sequence length to ≤ 12 across all scales and workloads. This produces deterministic query latencies and predictable tail performance, at the cost of a 2.14× insertion overhead (64.59 ns vs. 30.13 ns for LP) due to element displacement store cycles.
  • Pointer Indirection Penalty in Separate Chaining: Separate Chaining suffers from dynamic allocation overhead and pointer chasing, consuming 1.39× more memory (11.08 MiB vs. 8.00 MiB at N = 105). When table capacity exceeds the 25 MB L3 cache boundary (at N = 106), insertion latency surges to 102.44 ns due to DRAM line refills and allocator overhead.
  • Quadratic Probing Tradeoff: Quadratic Probing successfully prevents primary clustering while achieving the lowest overall memory footprint (4.58 MiB at N = 105).

3. Package Structure

  • paper/main.pdf: Complete 21-page IEEE two-column formatted research paper.
  • paper/main.tex & paper/paper.typ: Source files in LaTeX (IEEEtran) and Typst.
  • src/: Complete Rust source code for all four collision resolution algorithms and benchmark harnesses.
  • tests/correctness.rs: 61 integration tests (and 9 unit tests) verifying correctness against std::collections::BTreeMap.
  • results/raw_experiments.csv: 3,920 raw benchmark measurement rows across all distributions and scales.
  • results/summary_stats.csv: 560 aggregated statistical summary rows (medians, IQRs, probe counts, memory).
  • plots/: 17 publication-quality vector diagrams (7 algorithmic architectural diagrams and 10 empirical data graphs in PDF, SVG, and 300 DPI PNG).
  • 01_Reference_Papers/literature_inventory.csv: Reference inventory of 24 verified academic literature sources.

4. Hardware Testbed Environment

  • Processor: Intel Core i7-12700F (12 cores / 20 threads: 8 Performance cores @ 4.90 GHz, 4 Efficient cores @ 3.60 GHz)
  • Cache Hierarchy: 32 KB L1d per core, 1.25 MB L2 per P-core, 25 MB shared L3 LLC
  • Memory: 32 GB DDR4-3200 dual-channel
  • Operating System: Linux x86_64 (CachyOS, kernel 6.13+, performance governor)
  • Toolchain: rustc 1.100.0 (release mode with opt-level=3 and thin LTO)

5. Reproduction Instructions

  1. Run automated correctness tests:
    cargo test (verifies all 70 unit and integration tests; 0 failures)
  2. Run full benchmark suite:
    cargo run --release --bin experiment (generates 3,920 trials in results/raw_experiments.csv)
  3. Compute statistical summary:
    cargo run --release --bin stats_analysis (generates results/summary_stats.csv)
  4. Re-generate figures:
    python plots/plot_generation.py --csv results/summary_stats.csv
  5. Compile manuscript:
    typst compile paper/paper.typ paper/main.pdf
